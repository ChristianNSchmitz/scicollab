These are not gaps. They are features whose correct design output is a specification, not a screen.
Drawing a dashboard for key rotation or a settings panel for penetration testing would inflate the coverage number and mislead anyone reading it. Each card below states the feature, what it does, why there is no interface, and — the useful column — where a user would notice if it stopped working.
T12Encryption and key management
AES-256 at rest, TLS 1.3 in transit, envelope encryption with keys in an HSM, automatic rotation every 90 days. Per-tenant key separation; customer-managed keys available on the Institution tier.
NO UI BECAUSE
A key-management console for end users is an attack surface, not a feature. Rotation must not be skippable.
SURFACES AT
One line in the evidence pack, and the CMK option in the contract.
T11Independent penetration testing
Annual third-party test plus a test before any major architectural change. Findings triaged to a fix SLA by severity; the summary letter is published.
NO UI BECAUSE
It is a procurement artifact and a process, not a product surface.
SURFACES AT
The summary letter in the evidence pack. Camille's security office reads it; no user ever does.
H25Backup and geographic replication
Three copies across two EU regions, hourly incremental and daily full, 35-day point-in-time recovery, restore drills quarterly with the result recorded. RPO 1 hour, RTO 4 hours.
NO UI BECAUSE
Self-service restore of a shared multi-tenant store is a data-loss incident waiting to happen. Versioning already gives users per-artifact recovery.
SURFACES AT
The version selector is the user-facing half of this. The rest is invisible unless it fails.
T02Rate limiting and abuse protection
Per-account, per-IP and per-endpoint limits; progressive backoff; anomaly detection on bulk download and scraping patterns.
NO UI BECAUSE
Publishing the thresholds to end users teaches an abuser where the line is. API limits are published, because a developer needs them.
SURFACES AT
Message caps on DMs and headers on the API.
T05Observability
Structured logs, distributed tracing, RED metrics per endpoint, alerting on SLO burn rate rather than on raw error counts.
NO UI BECAUSE
Internal tooling. Exposing it would leak infrastructure detail and help nobody outside the on-call rota.
SURFACES AT
The latency figure and incident history on the status page.
T03 · T04Latency targets and storage scalability
Search p95 under 300 ms, feed under 500 ms, upload throughput at line rate. Object storage tiered hot/warm/cold with automatic migration by access pattern.
NO UI BECAUSE
Targets are engineering commitments. Tiering must be invisible or it becomes a decision users are unqualified to make.
SURFACES AT
The p95 on the status page, and cold-tier retrieval time noted on the storage view.
T06 · T07Feature flags and sandbox
Staged rollout by cohort with instant rollback. A persistent demo tenant with synthetic data, resettable, for evaluation and training.
NO UI BECAUSE
Flags are operator tooling. No A/B testing on scientific-record behaviour — two researchers must never see different validation rules.
SURFACES AT
The sandbox is a URL handed out during a pilot; the flags never surface at all.
T09 · T08Open standards and export guarantee
RO-Crate, BagIt, DataCite, Crossref, ORCID, CRediT, OpenAPI, SCIM, SAML, OCSF. A commitment that every object type has a documented open serialisation.
NO UI BECAUSE
A commitment, not a control. It shapes every export button rather than having one of its own.
SURFACES AT
Archival export — the no-lock-in guarantee is this card made visible.
T10Responsible disclosure and bug bounty
security.txt, a PGP key, a 72-hour acknowledgement commitment, safe-harbour language, and a paid bounty scaled by severity.
NO UI BECAUSE
Its audience is security researchers, who look for a text file at a well-known path, not a product page.
SURFACES AT
/.well-known/security.txt and a line in the transparency report.
T13Internal unit economics
Cost to serve per seat, per GB, per compute hour; gross margin by tier; the storage-growth curve against revenue.
NO UI BECAUSE
It is a board dashboard, not a product feature. Listed only because it appears in the backlog.
SURFACES AT
Nowhere in the product. Indirectly, in what the tiers cost.
O10 · O11 · O16 · O17 · O19 · O21
Integration connectors
Slack and Teams, Overleaf, JupyterHub, cloud storage, calendar, and no-code automation. Each is an OAuth connection plus a mapping, configured once.
NO UI BECAUSE
Six near-identical connect-and-authorise panels would be six mock screens saying the same thing. One integrations settings page covers all of them.
SURFACES AT
Settings → Integrations, and then inside the tool the researcher already uses.
O12 · O13 · O14 · O15 · O18 · O22
Sync and migration connectors
GitHub/GitLab bidirectional sync, ORCID read-write, repository deposit, protocols.io, ELN migration importers, instrument vendor APIs.
NO UI BECAUSE
The three that matter most are already drawn where they belong — as steps in a flow, not as a connector page.
SURFACES AT
ORCID import, external deposit, repository browser. ELN migration is a services engagement, not self-serve.
O01 · O06 · O20
Native apps, desktop sync, IdP role
Native iOS and Android, a desktop sync client for large local datasets, and SciCollab acting as an identity provider to third-party tools.
NO NEW UI BECAUSE
Native apps render the mobile screens already designed. Desktop sync is a menu-bar agent. Acting as an IdP has no interface at all beyond a consent screen.
SURFACES AT
J1 for mobile; a system tray icon; a standard OAuth consent dialog.
P10 · P18 · P20
Marketplace, partnerships, community edition
Commission on contract-research introductions, conference partnership channel, and a self-hostable open-source edition.
NO UI YET BECAUSE
Each is a business decision before it is a screen. A marketplace taking commission on research services needs a policy on conflicts of interest that does not exist yet.
NEEDS
A founder decision, then a design brief. Flagged rather than mocked.
L03 · L08 · L09 · L16
The four AI features held back
Writing assistance, alt-text generation, content translation, meeting-transcript extraction.
HELD BECAUSE
Each generates content that will be read as the researcher's own words. L08 is the closest to shippable — generated alt-text with mandatory human confirmation is defensible and directly serves S01.
RECOMMENDATION
Ship L08 next batch with the same review gate as method extraction. Hold the other three.
